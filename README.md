# LinkEntryGuard 1.0.0 — 全浏览器链接访问确认版

## 目标

本扩展**按 Chrome Profile 独立安装并生效**。不是只针对 Teams：只要 HTTP/HTTPS 网页准备在安装了本扩展的 Chrome Profile 中打开，不论来自 Teams 桌面版、TIM、邮件软件、其他浏览器或者 Chrome 自己的网页，默认先进入本地确认页。**未经“允许本次访问”点击，不应请求目标主页面。**

原有 Teams 网页保护仍然存在：Teams 网页中直接点超链接会被禁止，需要复制链接到地址栏再访问。手动地址栏粘贴网址同样**可能出现确认页**，这是为了避免对外部打开来源作不可靠的猜测。

**两道保护安装即生效，无暂停/关闭按钮。** 停用或卸载扩展会解除相关保护。

## 主要行为

| 场景 | 处理 |
| --- | --- |
| Teams 桌面版点击 `https://www.google.com`，目标 Chrome Profile 已安装扩展 | 尝试在发出目标主页面网络请求前重定向至确认页 |
| TIM、邮件等其他桌面软件打开 HTTPS 链接 | 同上；与来源软件无关 |
| Chrome 内任意 HTTP/HTTPS 网页点击普通超链接 | 由内容脚本阻止原点击，并在新标签显示确认页；原页面保持不变 |
| Chrome 地址栏手动粘贴并回车 | 可以出现确认页；点“允许本次访问”才打开 |
| 取消确认 | 不访问目标网站；关闭确认标签 |
| 允许本次访问 | 当前标签、当前 URL 取得一个短时许可；页面提交后撤销 |
| Teams **网页版**内点击链接 | 原有功能1：直接禁止，不出确认页；复制链接到地址栏后走确认页 |
| 未安装此扩展的 Profile | 不受该扩展约束 |

## 安装/更新

1. 解压下载的 ZIP，保留文件夹内的全部文件（包括 `rules` 目录）。
2. 在需要保护的 Chrome Profile 打开 `chrome://extensions`，打开“开发者模式”。
3. 原先若已加载 LinkEntryGuard：建议先**移除旧版本扩展**（不会删除源码文件夹），再点“加载已解压的扩展程序”选择新的 `LinkEntryGuard_1.0.0_ClickConfirm` 文件夹，避免旧源码路径仍被引用。
4. Chrome 可能提示扩展需要访问所有网站：这是全站主页面请求前确认所需的授权。不同意则不能实现此范围的防误开。
5. 单击扩展图标查看状态，应该显示 `ON`；若是“异常”，请打开扩展详情下的服务工作线程错误。
6. **先在单独测试 Chrome Profile 测试**，确认行为可接受后再安装到日常 Profile。

## 验收步骤（建议按序）

1. 已安装插件的 Chrome 手动输入 `https://www.google.com` → 先出现本地确认页。
2. 点击“取消访问” → 不加载 Google；重试网址，点击“允许本次访问” → 打开 Google。
3. 在受保护 Chrome 中打开一个普通网站，再左键点击其中一个 HTTP/HTTPS 链接 → 新开本地确认页，原网页不变。
4. 用 Teams **桌面版**点击 `https://www.google.com` → 应当先显示同样的本地确认页，而不是 Google 正文。
5. 用 TIM / 其他软件重复测试。确认弹窗及取消后不得访问目标页面。
6. 在 Teams **网页版**点击聊天链接 → 按功能1直接禁止；复制链接到 Chrome 地址栏 → 出现确认页后可以允许。
7. 用一个未安装插件的 Chrome Profile 验证其不受影响。

若第 4 步直接加载 Google，请到 `chrome://extensions` 查看扩展报错并检查是否为同一 Chrome Profile；也要确认浏览器中没有其他扩展/企业策略抢占导航。

## 技术结构

- `rules/failsafe.json`：随扩展安装生效的静态兜底阻断，HTTP(S) 顶层导航默认不允许静默直达。
- `background.js`：安装并持久化 `declarativeNetRequest` 动态重定向规则，使用 `regexSubstitution` 将原始目标 URL 送入 `chrome-extension://.../confirm.html#...`。
- `confirm.html` / `confirm.js` / `confirm.css`：本地确认页；确认按钮请求**当前标签的精准单次放行**。
- `page-click-guard.js`：拦截普通网页的真实左键超链接点击，避免纯客户端 SPA 链接完全绕过网络导航规则。
- `teams-guard.js`：保留原有 Teams 网页中直接禁止点击超链接的功能。
- `popup.*`：只读状态和本地最近 100 条记录；不设保护开关。
- `policy.js`：统一 URL 校验和安全域名显示。

## 安全和兼容性边界

1. **不是系统级防火墙**：只能约束已安装扩展且启用的 Chrome Profile。无法拦截未安装插件的浏览器或 Chrome 自身 `chrome://`、其他扩展页、`file://`、自定义协议等非 HTTP(S) 导航。
2. Chrome 的 `declarativeNetRequest` 只处理进入网络栈的请求。由站点 Service Worker / CacheStorage 直接返回的资源等特殊情况，不能保证相同拦截；原站点页面用按钮运行 `history.pushState` 也可能没有新主页面请求。不要宣传为所有场景 100% 拦截。
3. 某些 OAuth 登录重定向、普通刷新、浏览器前进/后退也会重复出现确认页；这是严格确认方案的预期取舍。
4. 用于放行的 URL 必须能构成 Chrome 支持的精确单次网络规则；长于 1600 字符的特殊 URL **安全拒绝**而不是永久放行。
5. **确认页网址可能包含原始链接**，该完整地址在确认标签中临时存在；日志只保存主机名，不保存路径、查询或完整 URL。
6. 一次性允许仅绑定当前 tabId 和完整请求 URL，页面提交时撤销；另有约 25 秒超时撤销和周期清理。确认失效时将拒绝继续打开，不会降级为永久允许。
7. Chrome 的权限提示可能较宽（访问 HTTP/HTTPS 所有网站）；本扩展不含远程脚本、不上传日志、不请求外部服务。
8. 企业策略、其他扩展的冲突、实验性 Chrome 版本可能影响效果。

## 本地测试

需要 Node.js（仅用于开发测试，最终用户不需要安装 Node）：

```bash
for t in tests/*.js; do node "$t" || exit 1; done
```

运行模拟测试覆盖：规则安装、静态兜底、精确单次许可、拒绝伪造确认、来源校验、日志隐私、SPA 普通链接点击、Teams 网页原有点击保护、异常 UI。真实 Windows Teams、TIM 和 Chrome 联调仍须在用户电脑上完成。版本号固定 `1.0.0`。
