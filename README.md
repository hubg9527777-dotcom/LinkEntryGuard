# LinkEntryGuard · Chrome 浏览器链接保护

**版本：1.0.2** · 构建 `1.0.2-r20261125.2` · Chrome Manifest V3 · 无第三方运行依赖。

## 功能

- **访问确认：** HTTP/HTTPS 网页在受保护 Chrome 中打开前显示确认页，可选「直接打开 / 无痕打开 / 取消访问」。不设置关闭保护的开关。
- **Teams 网页：** 仍然禁止在 Teams 网页中直接点击链接；可以复制网址到地址栏再访问。
- **正常站内切换：** ChatGPT 等网站的同源链接不再被网页点击脚本强制新开确认标签。若实际发生网络主文档导航，仍可能出现确认页。
- **悬浮备注：** 点击插件图标即可切换悬浮显示；开启后，在网页右上角靠近书签栏下沿显示一条紧凑备注。**拖动可调整位置，松手自动保存；拖到网页边界也不会跳回默认位置。双击文字编辑，点击空白处自动保存。** 点击插件弹窗中的「重置位置」可一键恢复默认坐标。
- **独立 Profile：** 备注、显示开关和悬浮位置保存在 `chrome.storage.local`，不同 Chrome Profile 各自独立。同一 Profile 的多个窗口共享备注。

- **黑白名单：** 白名单自动确认，黑名单优先阻止；支持精准网址、指定目录、整个网站、批量管理、导入导出、备注及撤销。
- **异常恢复：** 自动巡检、错误编号、重试、脱敏诊断；临时授权撤销失败时尝试启用高优先级紧急阻断。

## 安装或替换

1. 解压完整 ZIP，保留全部文件和 `icons/`、`rules/` 文件夹。
2. 打开目标 Chrome Profile 的 `chrome://extensions`，开启「开发者模式」。
3. 如果原来加载了 LinkEntryGuard，优先**用新版本文件覆盖原安装目录，再点击原扩展卡片上的「重新加载」**，可保留已有备注和记录。不要同时启用新旧两份插件。
4. 如需要新安装，使用「加载已解压的扩展程序」，选择含 `manifest.json` 的目录。
5. **一键无痕打开不再强制要求「允许在无痕模式下运行」。** 未授权时 Chrome 可以创建无痕窗口，插件不会访问无痕中的网页，也无法获取其窗口 ID；已授权时插件会采用受控的当前标签单次放行。若浏览器或组织策略禁用无痕窗口，Chrome 仍可能拒绝创建。

## 最少验收测试

1. 点击扩展图标，将「悬浮备注」打开；网页右上方出现小标签。
2. 双击标签输入「工作专用」，点击网页空白处保存；拖动标签后松手，刷新网页确认位置仍保持。
3. 用另一 Chrome Profile 安装同一文件夹，设置不同备注，确认互不影响。
4. 在 ChatGPT 中切换两条聊天；通常应无确认弹窗。点击外站链接仍应进入确认页。
5. 从 Teams 桌面版点击 `https://www.google.com`，应先显示确认页；「取消」不访问，「直接打开」在原 Profile 访问。
6. 点击「无痕打开」，应请求 Chrome 创建新的无痕窗口；普通窗口不应加载目标页。若 Chrome 管理策略禁用了无痕窗口，应显示错误，不回退为普通窗口。
7. 再次点击同一外部网址，必须重新确认，不能变成永久允许。

## 重要限制

- Chrome 扩展**无法绘制到真正的插件按钮或书签栏区域**，也无法读取插件图标的精确横向位置。悬浮备注默认在**网页可用区域的右上角**、可在网页范围内拖动（不能拖进 Chrome 工具栏），尽量对齐工具栏下方，不是 Chrome 原生 UI 的一部分。
- **同源客户端导航**（例如通常的 GPT 聊天切换）可以直接放行；同源链接若发起真正的 HTTP/HTTPS 主文档请求，Chrome 的请求前规则仍可能要求确认。这是兼顾普通浏览便捷和外部入口保护的边界。
- 无痕窗口不等于完全安全隔离。无痕功能可能受浏览器策略和 Chrome 版本影响。未授予扩展无痕运行权限时，Chrome 可以打开无痕窗口，但 LinkEntryGuard 不会继续保护无痕窗口内的页面。失败时不会自动回退到普通窗口。
- 当确认页覆盖了原有长期标签，选择无痕后会在原位置留下一个空白标签，以免误关闭原标签。插件自己新开的确认标签会尽量在成功转交无痕后关闭。
- 本插件无法覆盖 Chrome 内部页、单纯 `history.pushState`、`file://`、自定义协议或全部 Service Worker 场景；不要将其视为系统级安全边界。
- 插件的受信任日志只保存访问主机名；确认页临时使用完整网址的 URL fragment，敏感 URL 仍需注意地址栏历史和扩展页面状态。
- Chrome Popup 无法直接在其他网页上覆盖工具栏；悬浮备注在 HTTP/HTTPS 网页和本扩展的确认页显示。Chrome `chrome://` 内部页、原生新标签页、书签栏、扩展工具栏、Chrome 网上应用店和内置 PDF 查看器不能注入悬浮条；在这些页面可以悬停扩展图标查看备注。若用户授予“允许在无痕模式下运行”，无痕网页也可以显示备注。

## 开发测试

本项目运行时不依赖 npm 包。开发阶段需要 Node.js：

```bash
for t in tests/*.js; do node "$t" || exit 1; done
```

**测试性质：** 通过的 Node 测试属于浏览器 API 和 DOM 事件模拟；该环境下 Chromium 扩展后台被隔离策略阻止，仍需在实际 Chrome 中验证 Teams、无痕打开和书签栏下方的悬浮效果。

## 代码位置

- `background.js`：请求前规则、一次性允许、无痕窗口、安全消息和按 Profile 保存备注。
- `confirm.html/css/js`：三个访问选项、当前 Profile 备注。
- `popup.html/css/js`：悬浮开关、备注输入、状态和拦截记录。
- `floating-label.js`：30px 标签、鼠标拖动保存位置、双击编辑、失焦保存。
- `page-click-guard.js`：跨域网页点击确认、同源网页操作放行。
- `teams-guard.js`：独立 Teams 网页直接点击保护。
- `rules/failsafe.json`：网络拦截静态兜底规则。

本地修订不包含自动 Git 提交或 GitHub 推送，当前产品版本为 `1.0.2`。以下为历史变更记录。

## 第四轮安全复核（2026-11-21）

- 修复不同标签/弹窗同时保存备注与悬浮开关时可能发生的写入覆盖。
- 键盘进入悬浮备注编辑态必须是真实用户事件；后台不再输出可能含网址的原始异常对象。
- 弹窗“默认启用”是配置描述，不等于证明 Teams 内容脚本已在每个网页成功注入。
- 安装包附带最新 `SECURITY_AUDIT.md` 与新增 `tests/security-static.js`；版本为 `1.0.1`。
- 无法避免的 URL fragment 隐私、短时放行与 POST 导航兼容风险请参阅审核报告。**真实 Chrome 验收仍需在你的设备进行。**

## 实测截图中两项情况的说明（2026-11-22）

- **悬浮备注：** `confirm.html` 现在直接加载 `floating-label.js`，开启悬浮时确认页上也显示同一标签；关闭悬浮时保留确认卡片的 Profile 备注。请在普通 HTTP/HTTPS 网站中、关闭插件弹窗后确认悬浮条是否出现。Chrome 原生书签栏及工具栏无法被扩展悬浮覆盖。
- **无痕打开（新实现）：** 不再要求首次授权。未授权扩展访问无痕内容时，直接请求 Chrome 创建无痕窗口并打开目标网址；Chrome 可能不返回窗口 ID，这是预期行为。仅当你希望插件继续保护无痕窗口内的浏览时，才需要在扩展详情中允许在无痕模式运行。无痕创建失败不会回退为普通窗口。

## 悬浮拖动边界修复

- 移动到网页顶部、右侧边界时，坐标自动贴边（不进入 Chrome 原生书签栏），不会恢复默认位置。
- 浏览器取消指针事件、丢失指针捕获或者切换窗口导致拖动中断时，保存最后一个有效位置。
- 点击插件图标 →「重置位置」可以主动恢复初始位置（顶部 0px、右侧 110px），所有本 Profile 已打开的普通网页同步更新。
- 两项链接保护、无痕打开与备注自动保存逻辑保持不变；版本号 `1.0.1`。

## 1.0.1 名单功能增强

- 点击插件图标即可查看当前网址的状态（未加入、白名单、黑名单）和匹配的备注，选择精确网址或整个网站，加入、转换、修改备注、移除。
- 访问确认页也提供相同的快捷操作。黑名单禁用直接打开和无痕打开；白名单在后续访问时自动执行单次放行（可能短暂出现确认页）。
- “管理名单”打开独立页面，可搜索网址/备注、筛选名单、新增、编辑、移除。所有规则本地存储，按 Chrome Profile 独立保存；上限 300 条。
- 精确网址包含路径、查询参数，区分大小写，不包含 `#` 片段。整个网站仅匹配当前协议、域名和端口，不包含其他子域名。相同范围的同一规则可转为另一名单；重叠时黑名单优先，须移除匹配黑名单才能恢复放行。
- Teams 网页原有禁止点击规则仍优先执行；复制粘贴的网址由名单处理。无痕窗口如未授权扩展运行，不会继续保护其内部导航。
- 名单仅保护受扩展控制的主页面导航，不是网络防火墙。已加载页面不强制关闭；SPA 地址改变时对黑名单做事后补充检测，不能阻止已发生的请求。完整网址、备注按用户选择保存在本地，勿保存登录令牌等敏感参数。
- 本地源码版本保持 `1.0.1`，不改 GitHub 工作流或发布历史。

## 1.0.2 名单维护与保护可靠性增强（构建 r20261124.2）

- 点击插件图标 → 管理名单：批量粘贴、JSON 导入预览、导出、当前搜索结果全选、批量转白/转黑/删除、单条转换。导入冲突保留现有规则，不静默覆盖。
- 撤销上次修改：每次成功变更保存修改前的一份本地快照，可恢复；恢复后当前名单成为下一份快照。删除的规则可能仍在该快照内，备份和导出文件可能包含敏感网址。
- 指定目录：在集中管理页输入以 `/` 结尾的非根目录，例如 `https://example.com/work/`，仅匹配该同源目录及其下级路径（不匹配 `/work-other/`）；不接受查询参数。精确网址和整个网站的旧规则保持原义。仍最多 300 条。
- 右键网页或链接 → LinkEntryGuard · 管理链接名单：只预填管理表单，不自动保存或打开目标链接。新增 `contextMenus` 权限。升级时 Chrome 如要求重新授权，请检查扩展详情。
- 规则测试：输入网址检测当前命中结果及备注，不访问目标网站。
- 拦截记录 → 复制诊断：复制构建号、保护状态、存储与规则状态、临时放行数量等，不包含网址、备注或历史记录。
- 管理页刷新按钮可重新读取；旧快照不能覆盖其他窗口较新的名单。后台周期检查会修复全局确认规则并清理过期授权。
- 保持版本 1.0.2，既有资料不自动删除或上传。含指定目录新规则的名单不适合直接降级到不支持该范围的旧构建；请先导出备份。

暂不自动放行跨站登录链，不启用自动无痕名单、子域通配、规则停用或云端同步。真实 Chrome/Teams/TIM 验收仍需进行；不要把插件当作网络防火墙。
